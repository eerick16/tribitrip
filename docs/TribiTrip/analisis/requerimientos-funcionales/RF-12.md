# RF-12. Auditoría y trazabilidad

[Índice](../requerimientos-funcionales.md) · [Matriz](../trazabilidad.md)

## Especificación

**Objetivo:** Identificar responsables, cambios y vínculos comerciales.

**Actores:** Usuarios autenticados y personal técnico para logs.

*   Registrar fechas de creación y última modificación.
*   Identificar al usuario responsable de determinadas acciones.
*   Mantener vínculos entre clientes, solicitudes, oportunidades, cotizaciones y reservas. Las actividades de seguimiento están fuera del MVP.
*   Conservar el historial de las operaciones comerciales.

## Evaluación frente a la implementación

**Estado:** Parcialmente implementado.

Los documentos comerciales registran fechas y vínculos. Reservas y movimientos identifican responsables. Ficha y versiones conservan historial comercial. Los logs correlacionan solicitudes, mientras que F05 y una auditoría transversal de cambios carecen de implementación.

**Precondiciones:** Registro creado o modificado en una operación que conserva las marcas o el responsable.

**Postcondiciones:** La ficha o versión permite consultar el historial disponible; la respuesta HTTP lleva identificador de solicitud.

**Alternativas y validaciones:** El Request ID permite ubicar el evento técnico, mientras que las versiones corresponden a la historia comercial.
